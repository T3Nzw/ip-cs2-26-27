# Седмица 3 - Циклични процеси. Указатели и псевдоними

## 1. Циклични процеси:
### 1.1 Цикъл с предусловие: `while`
___
```cpp
while (<condition>)
    // тяло

while (<condition>) {
    /* 
    тяло: ред_1
    ...
    тяло: ред_n 
    */
}
```
- Този цикъл е с ПРЕДусловие, защото `<condition>` се проверява преди изпълнението на тялото. Следователно е възможно тялото да не се изпълни нито веднъж  
- Тялото на цикъла се изпълнява докато `<condtion>` се оценява като `true`
- Ако в тялото на цикъла не извършваме промени свързани с `<condition>` можем да попаднем в **безкраен цикъл**

### 1.2 Цикъл с постусловие: `do-while`
___
```cpp
do 
    // тяло
while (<condition>);

do {
    /* 
    тяло: ред_1
    ...
    тяло: ред_n 
    */
} while(<condtion>);
```
- Този циъкъл е с ПОСТусловие, защото `<condition>` се проверява след изпълнението на тялото. Следователно тялото ще се изпълни поне веднъж
- Както при `while` тялото се изпълнява докато `<condition>` се оценява като `true` и ако не променяме нищо от условието можем да попаднем в **безкраен цикъл**

### 1.3 Цикъл `for`
___
```cpp
for (<init>; <condition>; <update>)
    // тяло

for (<init>; <condition>; <update>) {
    /* 
    тяло: ред_1
    ...
    тяло: ред_n 
    */
}
```
- Цикълът `for` се използва, най-често, когато знаем точния брой стъпки, които ще изпълним
- Изпълнение:
1. `<init>` - Инициализация на управляващите променливи
2. `<condition>` - Оценяване на условието: 
    - `<condition> == true` -> Продължаваме към 3.
    - `<condition> == false` -> Цикълът приключва
3. Изпълнява се тялото на цикъла
4. `<update>` - Изпълнява се написания израз (това, което наричахме "променяне на нещо от условието" при `while` и `do-while` циклите)
5. Връщаме се на 2.
- Примери:
    - Отпечатва всички четни числа до `n` (включително)
    ```cpp
    for (unsigned num = 0; num <= n; num += 2)
        std::cout << num << " ";

    std::cout << std::endl;
    ```
    - Безкраен `for`
    ```cpp
    for(;;) std::cout << "Only Ctrl + C can save you" << std::endl;
    ```

### 1.4 Ключовите думи `break` и `continue`
___
- Понякога искаме директен контрол над поведението на даден цикъл. Затова се използват ключовите думи `break` и `continue`
- `break` - Прекратява цикъла веднага, независимо от условието на цикъла
- `continue` - Прекратява текущата стъпка, но не прекратява самия цикъл

### 1.5 Вложени цикли
```cpp
for (unsigned i = 0; i < N; ++i) {
    for (unsigned j = 0; j < N; ++j)
        std::cout << i << j << ' ';
    
    std::cout << std::endl;
}
```
- При вложените цикли, за всяка една стъпка на външния цикъл, вътрешния пробягва целия си интервал
- Ако използваме ключовите думи `break` и `continue` във вътрешния цикъл, те ще афектират само него, а не и външния

## 2. Указатели и псевдоними
### 2.1 Указатели
___
```cpp
<type>* <name> [=<memory_address>];
``` 
- Променлива, която пази адрес от паметта
- `nullprt` - указател, който не сочи никъде ("празен" указател)
```cpp
int variable = 10;
int* ptr = &variable;
```
- С оператор `&<var_name>` взимаме адреса на променлива

### 2.2 Псевдоними
___
```cpp
<type>& <name> = <variable>;
```
- Създаваме "ново име" към вече съществуваща променлива
- За разлика от указателите, за псевдонима не се заделя памет, а оттам и нямаме как да имаме "нулев псевдоним"

### 2.3 `*`, `&` и `const`
```cpp
// Този ред хвърля warning: duplicate 'const' declaration specifier
const int const * const ptr = &variableche;
```
- Най-лесно се ориетираме, ако четем отдясно, наляво:
    - `ptr e константен указател към константен const int`
- Какво забелязваме:
    - `const int*` е еквивалетно на `int const *` (е еквивалетно на `const int const *`)
- `<type> const * ptr` - Указател към константен `<type>`. Следователно не можем да променяме стойноста на променливата, към която `ptr` сочи, през `ptr`, но можем да променим стойността на `ptr`
- `<type>* const ptr` - Константен указател към `<type>`. Следователно не можем да променим стойността на `ptr`, но можем да променим стойността на променливата, към която `ptr` сочи
___
```cpp
const int& ref = variableche;
```
- Същите правила важат и за псевдоними, с уловката, че понеже за псевдонима не се заделя памет, то той си няма "собствена кутийка", следователно `<type>& const ref` не е възможен сценарии и **ХВЪРЛЯ ГРЕШКА** -> `error: 'const' qualifier may not be applied to a reference`
